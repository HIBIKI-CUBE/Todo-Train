# 17 — カレンダー体験

契約は変えない（[02](02-requirements.md) / [12](12-ui-design.md)）。カレンダーは運転しない。乗る対象は切符。掲示は線路を塞がない。着発が if-then。網は ATS。Hub に掲示リストを常設しない。ATO しない。日常の発車・停車・再乗車を確認で阻まない。確認は不可逆な操作だけ。指図しない。計器として必要十分な情報を乗務の現場に出す。

体験が悪いのは仕様違いではない。**契約が日常操作と擦れていない。** 直すときはここを先に読む。画面の作りはコードを見る。

## ずれ

カレンダーは仕事の材料ではない。時刻付きの枠は **占有の事実** であり、乗る対象でも、掃き出す元帳でもない。製品が見せるのは「いま何が枠を占めているか」「次に何が来るか」。そこから人が、今から何に乗るか自分で決める。

日常の中心は Hub の発車。発車・停車・再乗車は確認しない。状況認識は乗務の現場の計器（いまと次、時刻と分、題名）。着発の手は案内板の一行（今回だけ）とダイヤタブ。通過のままだと保護は効かない。確認は不可逆な操作だけ。指図しない。

## カレンダー上のものは一様ではない

時刻付き予定＝占有、としてしか見ていない。実際の予定は役割が違う。

| 種類 | 着発 | 通過 |
|------|--------|----------|
| 不可避の会議（1on1、面談） | 網の価値が高い。乗れない | 乗務中に気づかない |
| 任意・大会議 | 作業できない | 発車はできる。着発するまで網は無い |
| カレンダーに書いた集中ブロック | 走れない。本来乗りたい時間 | 掲示のまま |
| 期限だけの終日 / 仕事場所 / 誕生日 | 対象外で消える | 今日の休みが見えない |
| 仮 / 未回答 | 掲示される | 着発の判断ができない |
| 移動時間 | バッファなし | 帳場が足りない |

## シーン

見る・する・感じる。壊れる点は「感じる」。

### 初回

ダイヤタブを初めて開くと許可を求められ、24 時間の時計と用語が出る。Hub とは別世界に見える。着発するまで網は無いのが伝わらない。

許可を断ると図表に琥珀が出るだけ。設定へは届かない。Hub の計器も空。死んだ機能に感じる。

掲示するカレンダーを全部消すと掲示は消えるが、ダイヤは残る。隠す ≠ 通過、が図では分からない。

終日は静かに落ちる。休み・OOO・誕生日が状況認識にならない。

### 朝（Hub が中心）

運行の二行（いま／次）と、切符を持ち上げた案内板が占有の計器。リストではない。掲示のままでも次の枠は読める。Hub peek の 60 分尺に占有の門があり、塗りとの位置でこの切符が門の前で終わるかが読める。「今日何があるか」の全部はカレンダーアプリのほうが早い。ダイヤは毎日開かせない設計なのに、図表で着発するには開くしかない。

今日の会議を着発するのは図の上の今回だけ。件数でシートを開かない。今後もは別ジェスチャ。一括はない。

「今後も」は効いているか図表では確認しにくい。明日の図は無い。今夜、明日の重要会議を符号化できない。

### 発車（一番暑い経路）

発車は確認しない。掲示のままの会議中でも即走る。忙しい日に学校にしない。

ダイヤの直前に長い切符を発車すると、発車はできる。見積を縮める手は出ない。枠に入ると 60 秒で停車する。

着発した会議をスキップして走りたいとき、乗務現場で通過（今回だけ）。通過せずに再乗車すると同じ網に戻る。通過まで決着しないのは網であり、確認ダイアログではない。

会議そのものに乗りたいときは切符を別に出す。予定に乗る、ではない。連携したのに作業が 2 倍に感じる。

### 乗務中

Focus / Hub 運行（いま＋次の最大二行） / 案内板 / Mac PiP は占有の計器。Hub 運行は 60 分レール。Hub peek の 60 分尺に占有の門。塗りと門の位置で余裕・ギリ・踏み越しが伝わる。関係は視覚、題名と桁といま／次は文字。見出しや凡例は常設しない。持ち上げた切符の案内板は、枠がこの運行に掛かるときだけ 5 分セルが伸びて尺が寄り、燐光が熱を帯びる。占有は駅名標の行先票（題名が主）。Focus も残りが枠に掛かるときだけバーが寄る。予定の桁は主。予測は山形。掲示も含む。Lock / Live Activity / Widget には出さない。ダイヤ用のベルは足さない。

AlarmKit が活性なら終了ベルが次のダイヤ開始に畳まる。終了の音が会議の音に感じる。

掲示のままの会議に重なっているあいだは away を出さない。着発し忘れを乗務の現場で責めない。

アプリを閉じて会議すると、停車は次に開いたとき境界へ遡る。自分で停めていないのに過去が書き換わる。説明はダイヤタブにしかない。

ATS の停車は上限を食わない。枠が終わると静かな案内は消える。再乗車は人がする。ATO で戻さない（[02](02-requirements.md)）。計器で枠の終わりに自分で気づける。

### 予定が動く

時刻がずれると、着発したつもりが消える。知らされない。取消は消えるだけで分からない。カレンダー側で足した予定は、開くまで図表に乗らないことがある。

### 図表

個人・仕事・ファミリーが最初から全部出る。早食い、Focus Time、Busy、仮の RSVP も掲示。場所も人数も色も無い。着発する価値が読めない。

短い予定が連続すると帯が潰れる。

手動で時刻を引く起点が昼固定。「今から」ではない。朝に引くと過去になる。

履歴にダイヤだけ重ねるのは守る。掲示のままの会議の上を走ったように見えるのは、記録として誠実でない。

## 直す順

契約（発車は止めない、日常の発車・停車・再乗車を確認で阻まない、Hub に掲示リストを常設しない、掲示のままで ATS しない、ATO しない、月表示・書き込み・「これに乗れ」をしない）は壊さない。確認は不可逆な操作だけ。予定を仕事の材料にしない。着発／通過は件数でウィザードにしない。

1. **発車を阻まない** — 確認で学校にしない。ダイヤの網は ATS。意図して走る手は乗務現場の通過。
2. **乗務現場の認識** — いまと次の占有を計器に出す。掲示も含む。指図しない。Lock / LA / Widget には足さない。会議後は人が回す。ATS 停車で乗務が死なない。
3. **着発の摩擦** — 許可を断ったあとの行き場、終日が見えないこと、予定の移動が沈黙すること。

会議を切符にするのは最後。否定要件に触れる。占有が見えても「これに乗りたい」が残るなら、そのときだけ問い直す。

直すときの試し: 忙しい日に、掲示のまま発車しても学校にならない。Hub を見ただけでいまと次が読める。うっかりしていても枠の終わりに自分で気づける。着発した会議を意図して走れる。ATS で停めても再乗車できる。着発の手は残るが、件数でウィザードにならない。
