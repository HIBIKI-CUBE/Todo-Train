# 運行開始の盤

運行を始めるときに開く一枚の盤。運転士は MASTER を入れて計器を灯し、今日の占有と切符を一目で見てから DEPART を押して Hub へ出る。見た目と動きの正は参照モック `atmos-51-free.html`、数値はこの文書にある。モックの CSS クラス名、例データ、右側の調整パネルは Swift に写さない。モックと食い違う点（LOAD の上端と積み方、NEXT が通過の予定を数えないこと、READY 前の DEPART、COMM の窓と MAC 灯、SEQ 中の DEPART）はこの文書を正とする。

## 盤が答えること

盤は一日を計画する場所ではなく、一日の走り出しのきっかけと全体の見通しを渡す場所である。盤の上で答えるのは次の三つだけにする。

- 今日の占有はどう並び、いまどの状況にいるか（TIMETABLE・運転状況・ただいま板）
- 平常運転の時間があとどれだけ続くか、または次の平常運転までどれだけあるか（ただいま板・DEPART 横の行）
- 手元の切符は何で、今日の空きにどれだけ載るか（TICKETS・LOAD）

## 割り付け

格子は 370×780（外枠込み 372×782）、列 `118 / 1fr / 86`、行 `22 / 100 / 1fr / 50 / 150 / 22 / 92`、間隔 2。実機では一つの安全レイアウトの内側にこの比率のまま収める（[12](../12-ui-design.md)）。下の座標は格子左上を原点にしたモックの値で、比率の基準に使う。

| モジュール | 位置と大きさ | 中身 |
|---|---|---|
| sysbar（CHK・PHONE） | 2,2 / 368×22 | CHK: MSTR・CLK・TT・TKT の小さな灯。PHONE: 電池の窓（`FULL`／`CHG`／`64%`、20% 以下は `LO`）、EXT 灯、AWAKE 灯 |
| MASTER | 2,26 / 118×100 | キースイッチ（OFF／ON、レンズ `STBY`／`ON`）、PWR の LED 6 個 |
| 時計 | 122,26 / 160×100 | 7 セグメントの `HH:MM`、秒の小桁、コロンは秒の前半だけ点く |
| CLOCK | 284,26 / 86×100 | 確認キー（`STBY`／`OK`）、12/24 の押しボタン |
| TIMETABLE | 2,128 / 368×330 | 見出し行（AUTO/24H の切替、範囲の窓 `09–19 10H`、`運転状況` の見出し）、縦の時間割 266×261、運転状況の列 84×261、NEXT STOP IN／NEXT RIDE IN、確認キー |
| ただいま板 | 2,460 / 368×50 | 見出し `ただいま` と窓 304×38 |
| TICKETS | 2,512 / 280×150 | 見出し行（SEQ・確認キー）、段名（先発・次発・次々発・4・5…）、TODAY のレール、切符の窓 200×103 |
| LOAD | 284,512 / 86×150 | 空きのゲージ 40×120 と FREE の目盛り |
| COMM | 2,664 / 368×22 | TEST の押しボタン、結果の窓、RELAY 灯、MAC 灯 |
| DEPART | 2,688 / 368×92 | 左 214 幅: ロック行（MSTR・CLK・TT・TKT の灯と READY）、運転状況の行、先発の行、矢羽根 10 本。右: 押し棒 132×82（`出 発`、刻印 `DEPART`） |

大きさの配分は情報の要る量で決める。時間割と運転状況は縦に最も長く取り、時間の形をそのまま見せる。時計は一目で読める桁の大きさにとどめる。CHK・PHONE・COMM は状態が分かれば足りるので細い帯にする。押し棒は最後に押すものなので盤でいちばん大きな可動部にする。

運転状況の列は時間割の右に置き、縦の時間軸を共有する。列の内側は上下 3・左右 4 の余白で時間割の窓の内側と同じ高さにそろえ、同じ時刻が同じ高さに来るようにする。

## 目線の流れ

目線は左上の MASTER から始まり、時計、時間割と運転状況、ただいま板、TICKETS と LOAD を下り、右下の DEPART で終わる。最初に触るのが MASTER、最後に触るのが DEPART で、その間の計器はこの順に灯る。

DEPART を押す手元には、次に動くための情報を置く。押し棒の左に運転状況の行と先発の行があり、押す瞬間に「いまタスクに使える時間がどれだけあるか」と「Hub が最初に見せる切符」が同時に目に入る。押したら Hub へ出て、そのままタスクを始める。

## 触れるものと表示だけのもの

盛り上がった部品は押せる。凹んだ窓は表示だけで、押しても何も起きない。

| 押せる（盛り上がり） | 表示だけ（凹み） |
|---|---|
| MASTER のキー、CLOCK・TT・TKT の確認キー、12/24、AUTO/24H、SEQ、COMM の TEST、DEPART の押し棒 | 時計、範囲の窓、運転状況の列、NEXT の窓、ただいま板、LOAD、PHONE の窓、COMM の窓、DEPART 横の 2 行、すべての灯 |

凹みの中でも、次の二つは窓の中身に触れられる。

- 時間割の予定: 触るとその予定の着発と通過が切り替わる（今回だけ）。運転状況・ただいま板・LOAD はその場で計算し直す。
- 切符の窓とレール: 行に触るとその行の下に TODAY の区切りが移る。レールは押したまま上下に動かせる。SEQ の間は、行に触ると並べ替えの番号が付く。

## 起動の順序

MASTER を入れると盤に電気が来て、同時に `startService()` で運行が始まる。MASTER が一日を始める引き金で、DEPART は Hub へ出る操作である。一度始まった運行は MASTER を切っても続き、終えるのは運行終了だけ。

CLOCK・TT・TKT はどれをどの順に押してもよく、確認はそれぞれ独立に進む。押さなければ待ち時間のあと、まだ済んでいない確認を上から順に自動で始める。全部の確認が済むと READY が点く。DEPART は READY の前でも押せる。起動のあいだも出発は阻まない。

| 操作 | 動き |
|---|---|
| MASTER を入れる | `startService()` を呼ぶ。キーが回り、全灯チェックで盤の灯と刻印がすべて点く。消えたあと PWR の LED が 1 個ずつ 6 個まで積み上がる |
| 確認キーを押す | そのモジュールの起動の動きが始まる。済むと CHK の灯が点・滅・点・滅・点で知らせ、DEPART のロック行の灯が入る |
| 確認キーを押し直す | そのモジュールだけ未確認に落とし、起動の動きを最初からやり直す。READY も落ちる |
| 電気が来る前に確認キーを押す | 鈍い音だけで何も点かない |
| MASTER を切る | 盤を落とし、すべてのモジュールを未確認にする。運行は続く。切符の並びと TODAY の区切りは保つ |
| READY 前に DEPART を押す | 確認中・未確認のモジュールの起動の動きをその場で打ち切り、DEPART を押したときの動きに入って Hub へ出る |
| SEQ の間に DEPART を押す | SEQ を確定して抜け（選んだ順で先頭から並べる）、そのまま DEPART を押したときの動きに入る |
| MASTER を入れる前に DEPART を押す | 鈍い音だけで何も起きない |

モジュールごとの起動の動きは次のとおり。

| モジュール | 動き |
|---|---|
| 時計 | 背面照明が点き、`8` `88` `888` `8888` と桁が埋まり、いったん消えてから実時刻が灯る |
| TIMETABLE | 背面照明が点き、窓が 12 段で埋まり、`IN TEST` を出してから時間割と運転状況が描かれる |
| TICKETS | 背面照明が点き、カーソルの帯が 1 行ずつ増えたあと、切符が 1 枚ずつ並ぶ（1 枚ごとに軽い音と振動） |

### 間

既定値は次のとおり。「テンポ」が付いた値は自己診断と応答の速さで、表の値に 100/170 を掛けた長さで動く。

| 項目 | 既定 |
|---|---|
| 全灯チェックの長さ | 280ms |
| 自動で進むまでの待ち（最後の操作から） | 800ms |
| 自動のときの計器の間隔 | 120ms |
| 背面照明から中身まで | 50ms |
| PWR の LED 1 段 | 70ms × 0.6（テンポ） |
| PWR が満ちてから確認済みまで | 150ms（テンポ） |
| 時計の桁 1 段 | 110ms（テンポ）、`8888` のあと 300ms（テンポ）で実時刻 |
| 時間割の充填 1 段 | 32ms（テンポ）、充填のあと 150ms（テンポ）で `IN TEST`、300ms で描画 |
| TICKETS のカーソル 1 段 | 70ms（テンポ）、そのあと 150ms（テンポ）、切符 1 枚 110ms |
| CHK の点滅 1 段 | 60ms（テンポ） |
| システムのテンポ | 170% |

次に自動で始まるキーは縁をかすかに示す（`rgba(242,230,200,.3)` の 1px）。

### DEPART を押したとき

押し棒は MASTER を入れてからずっと押せる。READY の間だけ、矢羽根が押し棒へ向かって流れ続ける。押すと次の順に進み、最後に Hub へ切り替わる。READY 前に押したときも同じ順で、ロック行は点いている灯だけが抜ける。

1. 重い音と 30ms の振動。押し棒が 22ms ごとに 3 段沈む。
2. ロック行の灯が 28ms ずつずれて抜ける。
3. 矢羽根が手前から順に満ち、押し棒の柱が一瞬光る。
4. 盤のモジュールが下から上へ 22ms ずつずれて縁を光らせる（各 60ms）。PWR の LED は満ちたままにする。
5. `260ms（テンポ）+ モジュール数 × 22ms + 150ms` で Hub に切り替わる。

### 音と触覚

| 名前 | 中身 | 使う場面 |
|---|---|---|
| 軽い音 | 25ms の雑音、3200Hz 帯域 | キー、切替、桁の確定、切符が並ぶとき、灯が入るとき |
| 重い音 | 180ms の雑音を 400Hz 以下に絞り、90→55Hz の低音を重ねる | DEPART |
| 鈍い音 | 140Hz、30ms | 受け付けない操作 |
| 振動 | 10ms（操作）、8ms（区切りの移動）、30ms（DEPART） | 押せる部品を押したとき |

視差効果を減らす設定のときは、全灯チェック・桁の段・充填・カーソルを省き、各モジュールは最終の状態で灯る。DEPART の矢羽根は流さず薄く点けたままにする。

## TIMETABLE

縦の時間割に今日の予定を時刻の位置で並べる。濃い帯が着発した予定（ダイヤ）、縁取りだけの帯が通過の予定（掲示）で、行の頭に `着` と `通` の印を付ける。行は帯の中央の高さに置き、重なるときは上下にずらして引き出し線でつなぐ。左端に 0–24 時の小さな全体図を置き、今日の範囲を枠で示す。

範囲は表示する予定の最も早い開始を時で切り下げた時刻から、最も遅い終了を切り上げた時刻まで。4 時間に満たないときは開始から 4 時間にする。予定がないときは 6–24 時、24H に切り替えたときは 0–24 時。範囲の窓には `09–19 10H` の形で出す。

いまの位置から次の境目（予定の中なら、重なりを含めたその予定の終わり。外なら次の予定の始まり）までを帯で示し、秒で送る。NEXT STOP IN は予定の外にいるとき次の予定の始まりまで、NEXT RIDE IN は予定の中にいるときその終わりまでを `HH:MM:SS` で刻む。いまの帯と NEXT が見る予定は着発した予定（ダイヤ）だけで、通過の予定は停車駅ではないので数えない。使っていない側は減光して `--:--:--` を出す。

## 運転状況

運転状況は、時間割の範囲を「タスクに使える時間かどうか」で塗り分けた列である。出すのは事実だけで、どう走るかは運転士が決める。

### 分け方

1. 範囲の中の着発した予定（ダイヤ）だけを取る。通過の予定（掲示）は数えない。
2. 重なる予定は一つにまとめる。まとめた予定の間と、範囲の端から最初・最後の予定までが空きになる。
3. 空きと予定を次の規則で分ける。

| 区間 | 条件 | 状況 |
|---|---|---|
| 空き | 平常の長さ（60 分）以上 | 平常運転 |
| 空き | 平常の長さ未満 | ダイヤ過密 |
| 予定 | 見合わせの長さ（30 分）より長い | 見合わせ |
| 予定 | 見合わせの長さ以下で、隣の空きがダイヤ過密 | ダイヤ過密 |
| 予定 | 見合わせの長さ以下で、隣にダイヤ過密の空きがない | 見合わせ |

4. 同じ状況が続く区間は一本にまとめる。
5. 予定がない日は範囲全体を平常運転にする。

平常の長さは 20–120 分（5 分刻み）、見合わせの長さは 10–90 分（5 分刻み）の範囲で調整できる定数にする。既定は 60 分と 30 分。

### 見え方

| 状況 | 長い名前 | 短い名前 | 塗り |
|---|---|---|---|
| 平常運転 | 平常運転 | 平常 | 琥珀の薄い面 |
| ダイヤ過密 | ダイヤ過密 | 過密 | 琥珀の斜線 |
| 見合わせ | 見合わせ | 見合せ | 暗い面に明るい細い縁 |

区間の高さが 24 以上なら長い名前、13 以上なら短い名前、それ未満は塗りだけにする。過ぎた区間は不透明度 0.38 に落とす。いまの区間は明るい縁で囲む。赤は使わない。

## ただいま板と DEPART 横の行

ただいま板と DEPART 横の運転状況の行は、いつも平常運転を基準にして同じ言い方をする。いまタスクに使える時間ならそれがあとどれだけ続くか、そうでなければ次にタスクに使える時間までどれだけあり、そこからどれだけ続くかを出す。

| いま | 言い方 | 参照する平常運転 |
|---|---|---|
| 平常運転の中 | `平常運転　あと H:MM　HH:MMまで` | いまの区間 |
| ダイヤ過密・見合わせの中 | `過密`／`見合せ`　`平常運転まで H:MM　そこから H:MM` | この先で最も近い平常運転 |
| 範囲の始まりより前 | `始発前　平常運転まで H:MM　そこから H:MM` | この先で最も近い平常運転 |
| この先に平常運転がない | `過密`／`見合せ`　`本日の平常運転は終了` | なし |
| 範囲の終わりより後、または区間がない | `本日の運転終了` | なし |

- 状況の名前の前に、運転状況の列と同じ塗りの小さな札を付ける。始発前は塗りなしの細い縁にする。
- ただいま板の字の大きさ: 状況の名前 17、`あと`・`平常運転まで` の後の数字 24、`そこから` の後の数字 17、`あと`・`まで`・`平常運転まで`・`そこから` などの小さな字 10。数字は等幅。
- DEPART 横の行は同じ中身を 10 の一行に詰める。
- 両方とも TT の確認が済んでから灯る。表示は分が変わったとき、着発を切り替えたとき、平常の長さ・見合わせの長さを変えたときに書き換える。

### 参照している平常運転の強調

いまの言い方が参照している平常運転の区間は、運転状況の列の中でも同じ帯だと分かるように強調する。左に幅 3 の明るい棒、全周に明るい細い縁を付け、面を一段明るくする。過ぎた区間の減光よりこちらを優先する。参照がないとき（本日の平常運転は終了・本日の運転終了）は強調しない。

### 例

例の一日: 09:30–09:45 朝会（着）、10:00–11:00 定例ミーティング（着）、13:00–13:30 電話（通）、16:30–18:30 歯医者（着）。範囲は 09–19 時。

運転状況は 09:00–10:00 ダイヤ過密、10:00–11:00 見合わせ、11:00–16:30 平常運転、16:30–18:30 見合わせ、18:30–19:00 ダイヤ過密になる。13:00 の電話は通過なので平常運転を分けない。

| いま | ただいま板 |
|---|---|
| 08:30 | 始発前　平常運転まで 2:30　そこから 5:30 |
| 09:50 | 過密　平常運転まで 1:10　そこから 5:30 |
| 13:10 | 平常運転　あと 3:20　16:30まで |
| 17:00 | 見合せ　本日の平常運転は終了 |
| 19:10 | 本日の運転終了 |

08:30・09:50・13:10 では 11:00–16:30 の平常運転を強調する。

朝に詰まった日（08:00–08:15 メール確認・08:15–08:30 朝会・09:00–10:00 定例ミーティング・10:00–10:20 レビューが着、08:45 電話と 10:30 資料作成が通）は、08:00–09:00 ダイヤ過密、09:00–10:20 見合わせ、10:20–12:00 平常運転。09:30 は `見合せ　平常運転まで 0:50　そこから 1:40`。

## TICKETS

未完了の切符を Hub と同じ順で並べる。行は番号（7 セグメントの小桁）・題名・所要。左の段名は先発・次発・次々発・4・5…。

所要は見積もりではなく実際にかかる長さで出す。切符ごとの予測の中央値を使う。長さは TKT が灯ってから 700ms 後、6 段（1 段 70ms）で見積もりの長さから実際の長さへ伸びる。行の下地に、見積もりの長さを薄い面、伸びた分を斜線で敷く（120 分で行の幅いっぱい）。倍率や率の数字は出さない。

### TODAY の区切り

TODAY のレールと区切りは、今日ここまで乗るという運転士の決意の印である。予定としての意味は持たず、何も自動で決めない。行に触るとその行の下に区切りが移り、レールは押したまま上下に動かせる（1 行 21 ごとに止まる）。区切りより下の行は番号を 0.3 に薄くする。既定は 3 枚目の下。移したときは軽い音と 8ms の振動。

### SEQ

SEQ は切符の順を入れ替えるためのもの。TKT の確認が済むまでは鈍い音だけ。押すと並べ替えに入り、行を押した順に番号が付く。もう一度 SEQ を押すと、選んだ順で先頭から並び、選ばなかった切符は元の順で後ろに続く。並べ替えた順は Hub の順として保存する（`TicketSortOrdering.normalizedOrders`）。並べ替えに入って 1500ms、または最後に行を押してすぐから、SEQ の灯は速まりながら点滅し、1500ms で鈍い音とともに並べ替えを抜ける。このとき並びは変えない。同じ行を二度押すと鈍い音を鳴らす。SEQ の間に DEPART を押すと、並べ替えを確定して抜けてから出発する。

### 先発の行

DEPART 横の 2 行目は先発の行で、`先発　題名　所要` の形で TICKETS の先頭の切符を出す。Hub が最初に見せる切符と同じもので、SEQ で並べ替えたらその先頭に変わる。乗るのは Hub からで、DEPART を押しても乗車は始まらない。TKT の確認が済んでから灯る。未完了の切符がないときは空にする。

## LOAD

いまから TIMETABLE の範囲の終わり（運転状況と同じ範囲）までの空きに、TODAY の区切りより上の切符がどれだけ載るかを縦のゲージで見せる。例の一日なら 19:00 まで。空きは、いまから範囲の終わりまでの長さから着発した予定と重なる分を引いた長さ。いまが範囲の終わりより後なら空きは 0。空きの上端を FREE の目盛りと枠で示し、切符は下から積む。空きに収まる分は淡い面、はみ出す分は琥珀の面にする。空きが小さくても枠の高さは 22% 以上取る。区切りや着発が変わると 4 段（1 段 35ms、テンポ）で寄る。TT と TKT の両方が灯っているときだけ灯る。

## CHK・PHONE・COMM

### CHK

各モジュールの確認が済むと緑の灯が点く。盤の確認灯なので、乗務の信号色とは別に緑を使ってよい。赤はどこにも使わない。

### PHONE

電気が来ている間は `UIDevice.current.isBatteryMonitoringEnabled` を有効にし、盤を閉じたら無効にする。

| 表示 | 出所 | 出し方 |
|---|---|---|
| 電池の窓 | `UIDevice.batteryState`・`batteryLevel` | `.full` は `FULL`、`.charging` は `CHG`、それ以外は残量の `%`。20% 以下は頭に `LO`。`.unknown`（Simulator など）は `----` |
| EXT | `UIDevice.batteryState` | `.charging` か `.full` で点く |
| AWAKE | `AppSettings.keepAwakeWhileChargingInFocus`（既定オン）と EXT | 設定がオンで EXT が点いているときに点く。`FocusIdleTimerPolicy.shouldDisableIdleTimer` と同じ条件で、Focus 中に画面が消えないことを示す。盤そのものは idle timer を変えない |

### COMM

Mac コンパニオンとの通信を、中継までと Mac までの往復で確かめる。COMM は READY の条件に入れない。

| 表示 | 出所 | 出し方 |
|---|---|---|
| RELAY | `CompanionSyncRuntime` の WebSocket（`/v1/ws`、中継は `AppSettings.companionRelayURL`。既定は `RelayEndpoint.defaultURLString`、本番 `https://todo-train.hibiki-cube.dev`、DEBUG は `https://dev.todo-train.hibiki-cube.dev`） | TEST の `ping` に中継の `pong` が返ったら点く |
| MAC | 同じ `ping` に Mac の `echo` が返る | 返ったら点く |
| 窓 | iPhone の単調時計（`ContinuousClock`）で測った `ping` から `echo` までの時間 | 測っている間は `MEAS…`、届いたら `MAC 123MS`（3 桁、右寄せ） |

失敗の出し方は次のとおり。どれも鈍い音を鳴らす。

| 状態 | 窓 | 灯 |
|---|---|---|
| ペアリングしていない（`isPaired` が偽） | `NO PAIR` | RELAY・MAC とも消灯 |
| WebSocket がつながらない、または `pong` が 1500ms 以内に来ない | `NO RELAY` | RELAY を黄（`#f0c000`） |
| 中継に Mac がつながっていない（`echo` に `mac: false`）、または `echo` が 1500ms 以内に来ない | `NO MAC` | RELAY は緑、MAC を琥珀 |

#### 往復の経路

往復は中継の WebSocket に足す制御フレームで測る。中身は秘密を含まない平文の短い JSON で、保存も記録もしない。

1. 端末は `hello` に役割を足す: `{"t":"hello","contract":16,"minReadable":3,"role":"iphone"}`（Mac は `"role":"mac"`）。中継はソケットごとに役割と版を覚える（Durable Object の WebSocket の attachment）。
2. iPhone が `{"t":"ping","id":"<UUID>"}` を送る。
3. 中継はすぐ送り主に `{"t":"pong","id":"<UUID>"}` を返す。RELAY はこれで点く。
4. 中継は版 16 以上を名乗った `mac` のソケットへ `{"t":"ping","id":"<UUID>"}` を渡す。該当するソケットがなければ、送り主に `{"t":"echo","id":"<UUID>","mac":false}` を返す。
5. Mac は受けたらすぐ `{"t":"echo","id":"<UUID>"}` を送る。
6. 中継はそれを `iphone` のソケットへ `{"t":"echo","id":"<UUID>","mac":true}` として渡す。iPhone は同じ `id` の `ping` から `echo` までを MAC の時間として出す。

約束の版: 制御フレームと `hello` の `role` は足すだけなので、`contract` を 16 に上げ、`minReadable` は 3 のまま（`cd sync/worker && npm run contract:bump -- --note "WebSocket の ping・pong・echo と hello の role を足す"`）。中継は版 15 以下を名乗ったソケットや役割のないソケットには制御フレームを送らない。iPhone は中継の `hello` が 16 未満なら TEST で `GET /v1/hint/:pairingId` の往復だけを測り、RELAY を点けて窓に `RELAY 123MS`、MAC は presence（`SessionManager.macPresenceKnown`）で点けて時間は出さない。

守ること: `id` は UUID、フレームは 256 バイト以下。1 つのソケットからの `ping` は 1 秒に 1 回まで受け、超えた分は捨てる。往復の結果はどこにも保存しない。
