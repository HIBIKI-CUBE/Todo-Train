# 乗客モード（予定区間）設計

日付: 2026-10-06  
位置づけ: 方向性メモ（[18](18-passenger-cabin-direction.md)・同日・第3版）を製品意図の正とし、別紙の形式仕様書は書かない。本文に受け入れ条件を含める。  
対象読者: 実装者とプロダクトオーナー。

実装チケットは [Issue #66](https://github.com/HIBIKI-CUBE/Todo-Train/issues/66)。視覚の下限は [20](20-passenger-lcd-quality-refs.md)。この文書は乗客 UI を実装しない。

## 1. 目的と非目標

### 目的

時刻付きの予定枠を **駅間（区間）** として扱い、開始時刻に電車が来たとき、利用者が客として1タップで乗れるようにする。乗っているあいだは運転士になれず、画面はドア横の車内案内液晶だけになる。区間の終わり、または非常用ドアコックによる退出でのみロックが外れる。

Hub のマルス切符（仕事の発行と運転）と Focus 運転台とは別の面である。切符を「選んで発車させる」体験にはしない。

### 非目標（最初の切れ端）

- 自動乗車（ATO 相当）
- 直通（連続する予定を一本の乗車に繋ぐ）
- Mac Companion / Live Activity / Widget への乗客面の露出
- 到着ベル・実メロディ・実路線図・社名ロゴ
- Hub 切符セッション（`WorkSession`）への統合や、予定を切符化する導線
- docs/17 の契約全文の書き換え（後続。方針だけ §9 に記す）

## 2. 語彙

この面では **切符語を出さない**。発車・停車・再乗車・途中下車・発券などは Hub / Focus 用の語であり、乗客案内には載せない。

| 用語 | コード案 | 意味 |
|------|----------|------|
| **乗客** | passenger | 予定区間に客として乗っている立場。運転士ではない |
| **案内** | guide / LCD | ドア横の車内案内。次は／まもなく／ただいまの三態 |
| **乗る** | boardPassenger | 申し出を受けて乗客になる唯一の操作。候補一覧はない |
| **非常用ドアコック** | emergencyDoorCock | 乗車中のロック解除。長押し。下車・運転士・切符の語は使わない |
| **駅間 / 予定区間** | interval | イベントの単位。駅（点）ではない。開始〜終了の占有枠 |
| **申し出** | offer | ［乗る］が出ている状態。無視しても責めない |
| **乗客としての乗車** | `PassengerRide` | 切符の `WorkSession` とは別の記録 |

使わない（この面）: 切符、発車、停車、再乗車、途中下車、発券、マルス、運転台、乗り換え。

品質の下限はドア側の車内案内液晶の **文法**（次は／まもなく／ただいま、横長二帯、進捗ストリップ、開扉矢印）であり、特定社の商標・意匠の複製ではない。引用図の置き場と禁止は [20](20-passenger-lcd-quality-refs.md) と [references/passenger-lcd/](references/passenger-lcd/README.md)。

## 3. 状態機械

```
（対象枠あり）
    │
    ▼
 offer ──────［乗る］──────► aboard ──┬── 終了時刻到達 ──► arrived
    │                         │       │
    │ 無視・縮約帯のまま        │       ├── 非常用ドアコック ──► emergency
    │ 終了まで残す              │       │
    │                         │       └── 予定取消 ──► cancelled
    │                         │
    │                         └──（aboard 中は新たな offer なし）
    │
    └── 枠終了・取消・対象外 ──► （消滅。記録なし）
```

### 各状態

**offer**  
対象となる着発予定（または手動枠）の開始時刻に達した、または開始後にアプリを開いて区間がまだ続いている。前面に［乗る］、または裏で通知アクション「乗る」。乗らなくてもロックも記録もしない。初めは目立つパネル、しばらくしたら帯に縮め、枠の終わりまで「途中から乗る」を残す。途中乗車の時刻はタップ時点（遡らない）。枠が終わったあとに開いても遡って乗車扱いしない。

**aboard**  
乗客ロック中。全画面の車内案内のみ。Hub の発車・再乗車・発券、Focus の運転操作、新しい乗客申し出は不可（§7）。

**arrived**  
終了時刻に到達してロック解除。「ただいま」を短く出してから通常面へ。自動で切符に戻さない／自動再乗車しない。

**emergency**  
非常用ドアコック（約1.5秒長押し）で退出。確認ダイアログは出さない。「ドアを開けました」→ Hub。履歴に非常退出。枠が続いていれば再度 offer（途中から乗る）を出してよい。停車中の切符は自動では戻さない。

**cancelled**  
予定の取消（運休）。乗車中なら下ろしてロック解除。offer のみなら申し出を消す。

### 遷移の補足

- 予定の時刻変更: 終了表示と到着判定は追従する。
- 予定が重なる: 先発→次発。直通しない。先発が終わったら、次が来ていればまた1タップ。
- 終日・辞退 RSVP: 対象外。
- 自動で `aboard` に入れる遷移は、最初の切れ端では持たない。

## 4. 既存機能との交差

### SessionPhase / 切符セッション

`SessionPhase`（idle / running / paused / overtime）は **切符の乗務** 用のまま。乗客モードは別レーンとし、`SessionPhase` に `passenger` を足さない。aboard 中は乗務操作を拒否する（§7）。走行中に［乗る］を押した場合は、既存の ATS 待避と同じ道（`timetableHeld` 付きの停車）で列車を止め、それから `aboard` へ移る。

### timetableHeld / ATS

| 状況 | 振る舞い |
|------|----------|
| Hub で乗務なし | 開始時刻に［乗る］。乗ってからロック |
| 切符で走行中／超過 | Focus 帯に到着案内＋［乗る］。押すと待避してから乗車。押さなければ既存 ATS（約60秒） |
| 手動停車中 | 申し出る。停車上限は消費しない |
| すでに ATS 待避中 | 同じ枠ならそのまま［乗る］。案内文は「会議中は走っていません」等に置き換えてよい |
| 乗客として乗車中 | 新しい申し出なし。ATS の再発火で運転面に引き戻さない |

### 掲示（notice）と着発（adopt）

最初の切れ端の対象は **着発した予定と手動枠**。掲示のままは次でも可（入れないと「電車が来ない」と感じやすい点は §9）。掲示だけを対象にする場合も、［乗る］は「今回だけ着発」と同時でもよいが、slice 1 では外してよい。

### カレンダー許可

許可がなければ申し出は来ない（手動枠だけ可）。Hub では許可を求めない（既存どおりダイヤ側）。

### away / check-in / idle cabin

aboard 中は **止める**。乗客は乗務中の「まだ乗ってる？」対象ではない。ロック中に車内放送を出さない既存契約とも整合する。

### ApproachClear（接近クリアランス）

乗車の申し出を **優先** する。offer / aboard 中は盤を出さない（または閉じたあとに申し出）。シート表示中も、閉じたあとに申し出る。

### マルチデバイス

申し出とロックは **その端末だけ**。別端末が運転中でも、自端末の乗客面は自端末の状態に従う。クロスデバイスのロック伝播は後続（§9）。

### 裏にいる／ロック画面

開始時に通知1本（アクション「乗る」）。走行中は ATS 通知とまとめてよい。

## 5. PassengerLCD（UI 構造・設計レベル）

面の役割三分:

| 面 | 役割 |
|----|------|
| Hub 切符 | 仕事の発行と運転 |
| Focus 運転台 | 切符走行中の操作 |
| **車内案内（本案）** | 予定区間に客として乗っているあいだ |

### 三態

案内の主文は常に次のいずれか。

1. **次は** — まだ先。行先（題名）と着時刻の予告  
2. **まもなく** — 開始数分前〜開始直前。帯だけでも可  
3. **ただいま** — ドアが開いている／乗れる／到着直後の短い挨拶  

offer の開始瞬間は「ただいま」＋大きな **［乗る］** だけ。候補一覧は出さない（その時刻に乗れる電車は一本）。

### 帯とストリップ

- 横長の二帯（上: 主案内、下: 補足または進捗）  
- 区間の進捗ストリップ（開始→終了の位置。画素指定はしない）  
- 開扉側を示す矢印（どちら開きかは固定でよい。装飾として読む）

### 非常用ドアコック

案内画面の隅。補足「長押しでドアを開けます」。約1.5秒。完了後「ドアを開けました」→ Hub。

### offer の縮約

無視された申し出は、しばらくしたら帯に縮め、枠終了まで残す。責め文言・カウントダウン強要・「乗り忘れた」表示は出さない。

やらない見た目: JR ロゴ、実メロディ、実路線図、偽駅ナンバリング、切符券面の流用。

## 6. データ: PassengerRide（スケッチ）

`WorkSession` は使わない。切符の乗務履歴と混ぜない。

```
PassengerRide
  id: UUID
  intervalId: String          // 着発ブロック or 手動枠の安定 ID
  title: String               // 案内に出す題名（駅名標相当。主）
  intervalStart: Date
  intervalEnd: Date           // 変更追従のソースに紐づける
  boardedAt: Date             // タップ時点。開始より後なら途中乗車
  endedAt: Date?
  endReason: arrived | emergency | cancelled
  source: adoptedBlock | manualInterval
  deviceId: String?           // slice 1 は自端末識別で足りる
```

- 無視した offer はレコードを作らない。  
- emergency 後に同じ枠へ再乗車したら **別** `PassengerRide` でよい。  
- PDCA export の乗客ブロックは件数・時刻・endReason・aboard 秒だけ。題名・本文・deviceId は出さない。無視した offer は記録しないので export にも出さない。

## 7. ロック行列（aboard 中）

| 操作・面 | aboard 中 |
|----------|-----------|
| Hub 発車 / 再乗車 / 発券 / 切符操作 | 不可（案内のみ） |
| Focus 運転操作（延長・停車・到着など） | 不可 |
| ダイヤ着発／通過 | 原則不可（誤操作防止。閲覧は可でもよい） |
| 新しい乗客 offer | 出さない |
| 非常用ドアコック | **可**（唯一の手動退出） |
| ApproachClear | 出さない |
| away / check-in / idle cabin | 出さない |
| 予定終了による arrived | システムが解除 |
| 予定取消 | cancelled で解除 |

offer 中（未乗車）は通常どおり運転可能。責めもロックもしない。

## 8. 受け入れ条件（slice 1）

1. **着発予定または手動枠**だけが対象になる。終日・辞退は出ない。カレンダー許可なしでは手動枠以外来ない。  
2. 開始時刻に［乗る］が一つだけ出る。候補一覧はない。  
3. 無視しても記録・ロック・非難表示がない。帯に縮まったあとでも枠終了まで途中から乗れる。枠終了後のオープンでは遡及乗車しない。  
4. ［乗る］後は全画面案内＋§7 のロック。Hub／Focus の運転操作に戻れない。  
5. 走行中の［乗る］は `timetableHeld` 待避ののち aboard。押さなければ既存 ATS。  
6. 終了時刻で arrived。短く「ただいま」のあと通常面。自動再乗車・自動で切符復帰なし。  
7. 非常用ドアコック長押し（約1.5秒）で emergency。確認ダイアログなし。履歴に非常退出。枠継続中は再 offer 可。  
8. 予定取消で cancelled。乗車中ならロック解除。  
9. PassengerLCD に三態・二帯・ストリップ・開扉矢印がある。非常用ドアコックが隅にある。  
10. `PassengerRide` が WorkSession と分離して残り、endReason が区別できる。  
11. ApproachClear より申し出が優先。aboard 中に away / check-in が飛ばない。  
12. 自動乗車設定は存在しない。

## 10. リスク（必要なものだけ）

- **契約文書との一時的な緊張**: 実装が先行すると「カレンダーは運転しない／乗る対象は切符」と読み手が衝突する。slice 1 出荷前後で 17 を更新する。  
- **ロックの強さ**: 非常用ドアコックを初手から置くことで緩和済み。発見性が低いと閉じ込め感になるため、隅でもラベルは省略しない。
