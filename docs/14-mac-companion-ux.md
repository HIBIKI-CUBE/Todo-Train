## 提案する体験（v1）

仕事中は Mac を正面にしている。iPhone は机の端か Focus 表示のまま。列車の切符を並べたり、到着の 3 択をしたりはしない。

| 要素 | 提案 |
|------|------|
| 殻 | **メニューバー常駐**（Dock に出さない accessory）+ **乗務中の PiP**（四隅に投げられる小さなカード） |
| バー上 | 短いタイトル（切れ）+ 残り。乗務なしはアイコンのみ |
| クリック | 左クリックはポップオーバー。未ペアなら即ペアリング。ペア済みならフルタイトル、大めの残り、停車 / 再乗車。右上の歯車とメニューバー右クリックは同じ設定ウィンドウ |
| PiP | 走行中・超過・停車中だけ出す。タイトル大、経過バー＋残り。ホバーで停車 / 再乗車。左右の端へドラッグすると Peek（タイトル断片）。自動では隠さない。フォーカスは奪わない |
| 操作 | **停車と再乗車。** 到着・延長・割り込み・発券・運行開始/終了は iPhone |
| ログイン時起動 | 既定 ON（道具として常にそこにある） |
| 設定 | **ウィンドウ。** 吹き出しの歯車またはメニューバー右クリック。解除は確認あり。ペアリング用の別ウィンドウは持たない |
| ウィンドウ / Hub | Hub や大きな運転台は持たない。乗務中の PiP だけ例外 |

メニューバーは Live Activity の短い横目。PiP は「いま何に乗っているか」を画面の隅へ常時出す面。運転台そのものではない。

## 状態（ユーザーが見るもの）

同期の `phase` / ack を、画面の言葉に落とす。ポーリングしているようには見せない。残りは端末内の Date 計算。

| 状態 | バー | ポップオーバー | PiP | 停車 / 再乗車 |
|------|------|----------------|-----|------|
| 未ペア | アイコン | クリックで即ペアリング（正方のカメラ枠 + Mac の QR） | 出さない | なし |
| 乗務なし | アイコン | 「乗務なし」 | 出さない | 置けない |
| 走行中 | タイトル切れ + 残り | フルタイトル + 残り + 停車 | タイトル + 経過バー + 残り。ホバーで停車 | 停車できる |
| 超過 | タイトル切れ + 超過の残り | 超過であることが分かる。3 択は出さない | バー満杯、残りは `+m:ss`。3 択は出さない | 停車できる（到着の判定は iPhone） |
| 停車中 | アイコン、または「停車中」短い表示 | タイトル + 停車中 + 再乗車 | 出す。ホバーで再乗車 | 再乗車できる |
| 送信中 | 走行中 / 停車中のまま | 停車・再乗車ボタンは残して押せない。「iPhone に送った」。連打しない | 同じ。ボタンは残して押せない | 同じ cmd を再送しない |
| 送れなかった | 走行中 / 停車中のまま | 一行。停車上限 / 乗務が変わった / 停車中ではない など。ウィザードなし | 同じ一行 | もう一度押せる |
| 回線なし | 最後の snap を Date 計算で仮表示、またはアイコン | 「iPhone とつながっていない」 | 最後の snap を Date 計算で仮表示 | 置ける（FIFO に残る。届くのは iPhone が前面に来てから） |

「送れなかった」の文言は ack の `error` だけを使う。サーバの生エラーやスタックは出さない。

超過 3 択・車内放送・臨時停車シートは Mac に出さない。iPhone の Focus が本尊。

## 停車 / 再乗車の手触り

1. ポップオーバー、または PiP のホバーで停車または再乗車を押す
2. すぐ「iPhone に送った」にする。ボタンは残して押せなくする（楽観的に走行を止めない／再開しない。本尊は iPhone）
3. ack `ok` + snap が `paused` / `running` → 「停車中」または残り
4. ack `ok: false` → 直前の snap のまま、一行理由
5. iPhone が背面 → 送信中のまま待ち。前面に来たとき反映。Mac から起こさない

停車上限に当たったときは iPhone 側で解決シートが出る（既存）。Mac は「停車できません（停車上限）」だけで、解決 UI は持たない。

## 乗務 PiP

ADHD はすぐに他のことを始めてしまうので、乗務があるあいだは画面の隅に「何に乗っているか」と残りを出し続ける。

- 既定は右下。ドラッグして離すと四隅へスナップ。位置は端末に残す
- 左右の画面外へ十分ドラッグすると Peek（色付きタブにタイトル断片＋シェブロン）。クリック、または内側へドラッグで戻す。自動では隠さない
- ホバーで下段が停車 / 再乗車に差し替わる。到着・割り込み・延長は出さない
- nonactivating の `NSPanel`。ホバーや停車を押しても前面アプリのキー入力を奪わない。全 Space・フルスクリーン補助。Dock には出さない

## ペアリングの体験

プロトコルは [13](13-sync-mac-companion.md)。数字を見比べさせない。画面を Mac に向ける一動作。

**一発（主経路）**

1. 未ペアでメニューバーをクリックすると、吹き出しがそのままペアリングになる（別ウィンドウは出さない。追加のボタンも踏まない）
2. 吹き出しの大半は **正方の大きなウェブカメラ枠**。四隅は QR 用。読めたら緑、失敗は赤。Mac 側 QR はその枠の下に載せる
3. iPhone は自分の QR（不透明に描画）+ 正方の前面カメラ枠。説明は「画面を Mac に向ける」
4. 利用者は端末の背面を見ることになる。狙いは Mac のプレビューで合わせ、読めたら haptic
5. 両方読めたら iPhone を自分に戻して Face ID。Mac は **自動で Touch ID**（吹き出しが閉じても確定は続ける）
6. iPhone がつながったあとにオファーを消さない。Mac の Keychain 書き込みが終わるまで待つ
7. 吹き出しを閉じたら、未読取ならカメラとオファーを止める。読取後の Touch ID 中は止めない
8. 収録・スクショ・背面でやり直し

セルフィー中は顔がカメラ側に無いので、Face ID を同じ姿勢でやらない。

**カメラの無い Mac（例外）**

貼り付けと逐次読取。主経路にしない。

解除は iPhone の設定でも Mac の設定でもできる。Mac の設定は吹き出しの歯車かメニューバー右クリック。解除は確認してから Keychain を消す。リカバリは確定後の任意。書き写しのみ。QR にしない。

**どの Mac か**

iPhone の設定と Mac の設定に、コンピュータ名とペア識別子（`pairingId` の先頭 8 桁）を出す。名前は QR の任意 `n`（秘密ではない）。既存のペアは再ペアするまで iPhone 側に名前が無いので、識別子が同じなら同じペア、で照合する。

## やらないこと（体験）

| やらない | 理由 |
|----------|------|
| Hub / マルス券 / 発券 / 並べ替え | 掃き出しは iPhone。机の横目用ではない |
| 履歴・週次・定時の案内 | 振り返りは iPhone |
| 到着・延長・割り込み | フォーカスの意志は運転台に残す |
| 車内放送の 4 択 | iPhone Focus / 通知 |
| Dock アプリアイコン常駐 | メニューバーで足りる |
| 大きな常時ウィンドウ / Hub 複製 | 横目のコストが増える。設定ウィンドウと乗務中の小さな PiP だけ例外 |
| 乗務なしの常時 PiP | 乗っていないときは出さない |
| PiP のタイムアウト自動隠し | ADHD の「常に目に入れる」と逆になる。隠すのは端へのドラッグだけ |
| 同期の仕組み説明（E2E、Workers） | 設定の一行「この Mac だけが読める」程度まで |
| QR と照合数字を同時に出す | 使わない。照合数字自体を人の防御にしない |
| ペアリング QR に秘密を載せる | [13](13-sync-mac-companion.md) |
| 片側の「許可」タップだけで連携済みにする | 録画を見ている第三者が片側を代替できる |
| 最初の読取のあとすぐ Face ID | 見ない照合のゴム印になる。双方の光学読取のあと、端末を自分に戻してから |
| 裏カメラに持ち替えて二度読むのを主経路にする | セルフィー一動作。カメラ無し Mac だけ例外 |

見た目は [12-ui-design.md](12-ui-design.md) に合わせる。メニューバーはシステム標準。Focus の純黒運転台は macOS に複製しない。PiP は iOS のピクチャ・イン・ピクチャに近い黒カード＋琥珀の経過バーに留める。

## 確認してほしいこと

同期（E2E / CFW / 起こしなし）は [13](13-sync-mac-companion.md) で確定済み。ここでは体験だけ。

1. **殻はメニューバー accessory でよいか。** **確定（2026-09-12）。** ペアリング用の別ウィンドウは持たない。未ペアのクリックは吹き出しで即ペアリング。乗務中の小さな PiP は同日に追加（Hub 窓ではない）
2. **操作は停車だけでよいか。** **確定（2026-09-12）。** 机から再乗車も置く。到着・延長は iPhone
3. **乗務なしのときバーに文字を出すか。** アイコンのみ（提案）か「運休」か
4. **超過を Mac でどう見せるか。** 提案は表示だけ（3 択なし）。超過そのものを出さない方がよいか
5. **送信中（iPhone が背面）をどこまで丁寧にするか。** 提案は「送った」で待つ。失敗扱いにするか
6. **Mac にカメラが無いときの落とし方は例外でよいか。** 主経路はセルフィー一動作（Mac カメラ必須）

3–6 が埋まれば、この紙を確定にする。土管の再議論はしない。
