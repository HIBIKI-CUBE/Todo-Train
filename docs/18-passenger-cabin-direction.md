# 車内案内パネル — 方向性メモ（読む用）

日付: 2026-10-06（第3版）  
目的: 仕様・設計の前に、方向が合っているかを人が確かめられるようにする。  
まだ受け入れ条件や API は書かない。

設計（受け入れ条件つき）は [19-passenger-interval-design.md](19-passenger-interval-design.md)。視覚の下限と引用の範囲は [20-passenger-lcd-quality-refs.md](20-passenger-lcd-quality-refs.md)。実装は [Issue #66](https://github.com/HIBIKI-CUBE/Todo-Train/issues/66) の別作業。この文書は乗客 UI を実装しない。

確認済み（利用者）: 予定＝駅間／乗客ロック／マルス級の文法密度／最初の切れ端＝乗客ロック＋案内パネル／**ロック解除は初手から**。

---

## ひとことで言うと

予定は駅ではなく**駅間**である。決まった時刻に電車が来たら、客として1タップで乗る。乗っているあいだは降りられないし運転士にもなれない。画面はドア上の車内案内だけ。終わるか、非常用ドアコックで開けたときだけ外に出られる。

Hub のマルス切符を「選んで乗る」体験にはしない。

---

## 乗車の体験（切符との違い）

切符は、自分が選んで発車させる。予定は、時刻が来て電車が来る。

流れのイメージ:

1. **まもなく**（開始数分前）— 帯に「まもなく ◯◯ 10:00–11:00」。触らなくてよい。
2. **ドアが開く**（開始時刻）— 案内に「ただいま」と大きな **［乗る］** が一つだけ。候補一覧はない。その時刻に乗れる電車は一本。
3. **乗ったあと** — 全画面の車内案内。Hub の発車・再乗車・発券などは使えない。
4. **終わり** — 次の駅に着く。ロックが外れる。「ただいま」を短く出してから通常へ。自動では切符に戻さない。
5. **途中で出たい** — **非常用ドアコック**（長押し）。確認ダイアログは出さない。履歴に「非常退出」。予定が続いていれば、あとから「途中から乗る」は残してよい。

無視したら責めない。ロックも記録もしない。初めは目立つパネル、しばらくしたら帯に縮め、予定の終わりまで「途中から乗る」を残す（会議は遅れがち）。途中乗車の時刻は押した時点（遡らない）。予定が終わってからアプリを開いても、遡って乗車扱いにはしない。

自動で乗せることは、最初はやらない。ロックが強い・仮予定がある・「指図しない」契約に触れるため。あとで「今後も着発」単位の設定にしてもよい。

運転中に予定が始まったら: ［乗る］で既存の ATS 待避（`timetableHeld`）と同じ道で列車を止め、それから客席へ。押さなければ、今どおり約60秒後に ATS が止める。Focus が閉じたあとも Hub 側でドアは開いたまま。

---

## ロック解除（初手から）

名前: **非常用ドアコック**（下車・運転士・切符の語は使わない）。

場所: 案内画面の隅。補足は「長押しでドアを開けます」。約1.5秒。押したあと「ドアを開けました」→ Hub。停車中の切符は自動では戻さない。

---

## アプリの状態と振る舞い（要約）

| 状況 | どうするか |
|---|---|
| Hub で乗務なし | 開始時刻に［乗る］。乗ってからロック |
| 切符で走行中／超過 | Focus 帯に到着＋［乗る］。押すと待避してから乗車。押さなければ既存 ATS |
| 手動停車中 | 申し出る。停車上限は消費しない |
| すでに ATS 待避中 | 同じ枠ならそのまま［乗る］。案内で「会議中は走っていません」を置き換えてよい |
| 乗客として乗車中 | 新しい申し出なし。運転操作不可。案内のみ |
| 予定終了 | 到着してロック解除。自動再乗車なし |
| 予定の時刻変更 | 終了表示を追従 |
| 予定の取消 | 運休として下ろし、ロック解除 |
| 予定が重なる | 先発→次発。直通しない。終わったら次が来ていればまた1タップ |
| 掲示（未採用）だけ | 控えめな［乗る］で「今回だけ着発」と同時でもよい。最初の切れ端では外してもよい |
| 終日・辞退 | 対象外 |
| カレンダー許可なし | 来ない（手動枠だけ可）。Hub では許可を求めない |
| 裏にいる／ロック中 | 開始時に通知1本（アクション「乗る」）。走行中は ATS 通知とまとめる |
| 途中でアプリを開く | 途中から乗る可 |
| 終わったあとで開く | 何もしない |
| シート表示中 | 閉じたあとに申し出 |
| 接近クリアランス | 乗車の申し出を優先 |
| 乗客中の away・check-in・idle cabin | 止める |
| 別端末が運転中 | 自分の端末だけで申し出・ロック |

## 三つの面

| 面 | 役割 |
|---|---|
| Hub 切符 | 仕事の発行と運転 |
| Focus 運転台 | 切符走行中の操作 |
| **車内案内（本案）** | 予定区間に客として乗っているあいだ |

品質の下限（マルスと同型）: **次は／まもなく／ただいま**、横長二帯、進捗ストリップ、開扉矢印。ロゴ・実メロディ・実路線図は使わない。照合用の引用図は [references/passenger-lcd/](references/passenger-lcd/README.md)。

---

## いちばん小さい切れ端

1. 着発の予定と手動枠だけ（掲示は次でも可）
2. 切符のセッションとは別の「乗客としての乗車」記録（非常退出／到着／運休）
3. ［乗る］申し出（前面の帯＋裏の通知）と途中から乗る
4. 乗車後は案内全画面＋運転ロック
5. 終了で到着解除／非常用ドアコック
6. 液晶の三態＋帯＋矢印

外す: 直通、Mac、Live Activity／Widget、自動乗車設定、到着ベル。

## まだ決めておくとよいこと（任意）

- 契約文書（「乗る対象は切符」「会議を切符にするのは最後」など）を、乗客モード用にどう書き換えるか。
- 営業日が開く前の会議で、乗ると営業も開始するか、独立にするか。
- 掲示のままの予定を最初の切れ端に入れるか（入れないと「電車が来ない」と感じやすい）。
- 別の iPhone／iPad にもロックを跨げるか。
