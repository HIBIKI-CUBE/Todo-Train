## 2. 製品上の役割と置く場所

接近クリアランスの役割は二つに限る。一つはアプリを開く理由になること、もう一つは開いたことへの小さなご褒美になることだ。深くのめり込む場所にはしないし、タスクを片づけている最中の注意を奪ってもいけない。利用者に ADHD 傾向がある前提で、タスクの流れから気を逸らす玩具は製品として失敗と見なす。以下の配置・セッション・終了の決まりは、すべてこの役割から来ている。

置き場所は Hub の「盤」である。盤は Hub を開いたときに目に入るミニ指令盤で、本物の運行状態（運行中／運休／停車）と玩具が同じ面に同居する。玩具だけの独立画面や全画面の「室」は作らない。盤の見せ方は次の 2 パターンを許す。

| パターン | 内容 | 使う場面 |
|---|---|---|
| A. 常設盤 | Hub 内に盤をそれなりに大きく置き、そのまま遊べる | Hub がタスク操作の主画面でない場合 |
| B. 気配表示→展開（推奨） | 普段は運行帯とランプの気配だけを見せ、盤への意図的な操作で遊べる大きさに展開する | タスク操作と同じ画面に盤が並ぶ場合 |

フィジェットがタスクの流れから注意を奪うおそれがある画面では B を選ぶ。B の気配表示では、針・接近・Taptic を動かさない。運行帯の運休・停車は気配表示でも読めるようにする。展開は利用者が盤に触れたときだけ行い、時間経過・タスク完了・通知などをきっかけに自動で展開しない。

次の点は A・B どちらでも守る製品ルールである。

- タスク完了画面に、フィジェットのオーバーレイや「遊ぶ？」の誘いを出さない
- 盤へ戻るよう促す表示・通知・バッジを出さない
- ホームウィジェット（「窓」）への接近クリアランス搭載は v1 の対象外とする。窓は既存方針（明かり＋てこ程度）のまま

盤の具体的な大きさ（pt）と、B の展開・収納のアニメーションは未決で、14 章に残す。

## 3. 体験の一文と 3 秒ループ

体験を一文で書くと次のとおりになる。

> 接近の針が寄ってくる → 窓で押して刺す → カチッ → 列車がパッと抜ける → すぐ次の接近

この玩具は Space Orbit と同じ棚に座る暇つぶしで、X や YouTube に勝とうとはしない。数十秒いじって、ついでに本物の運休・停車が目に入り、自分で閉じる。生産性を上げる道具でもない。

1 回の接近は長くても 1.5 秒ほどで一巡し、3 秒あれば 2 回前後刺せる。ため（ギュッ）は接近そのものに残し、刺したあとの空き時間は削る、というのが v7 の時間配分である。

1. ギュッ: 針が左から右へ動く（tier 0 で 1180ms）。窓の手前から弱い Taptic が刻まれ、窓に近づくほど間隔が詰まる。
2. 刺す: プレイヤーが開通ボタンを押す（touch down）。押した時刻が良帯なら重いクリック、可帯なら短い噛みつき、帯外なら赤い却下。
3. パッ: 成功なら列車シルエットが短く抜け、良なら 170ms、可なら 135ms 後には次の接近が始まる。不可でもループは止まらず 290ms 後に次へ進む。

## 4. 変えないもの／やらないもの

以下は製品側のロックで、実装の都合で崩してはいけない。A/B やチューニングの対象にもしない。

| 区分 | ロック内容 |
|---|---|
| 役割 | アプリを開く理由と、開いたことへの小さなご褒美だけ。深い沈み込み先にしない。タスク操作中の注意を奪わない |
| 席 | Idle／フィジェットの席。Space Orbit の隣。X／YouTube に勝つ設計にしない。深い生産性機能にしない |
| 見た目 | メカ／機械クールなパネル。鉄道写実（実在の車両・駅名・ダイヤ）にしない |
| フィードバック | Taptic Engine が主役。音は出さない（SOUND 設定もなし）。Taptic と視覚だけで手触りが成立すること |
| 数値 | 点数・連続数・回数を通貨にしない。HUD に数字を出さない（debug ビルドのみ可） |
| 難易度表示 | ランプの色と強さだけで示す。段名（一字の漢字ラベルなど）を画面に出さない |
| 称賛 | 称賛は FX と Taptic の強さだけで表す。段に応じて変わる称賛文は出さない |
| 失敗 | ソフト却下。ミスしてもループは続く。死画面なし。責め文言、空白日の催促、出席扱いをしない |
| 玩具の境界 | 玩具の回送は `startService()` を呼ばない。切符の題名を出さない。到着としてクレジットしない |
| 本物の状態 | 本物の運休・停車は同じ盤の上で常に読めること。初出荷から実状態を配線する |
| 長さ | 短いセッション（約 40 秒または約 14 クリア）で静かになる。自動再開しない。終わりはプレイヤー自身が決める |
| 入力 | 離散ワンアクション（開通ボタンを押す一回＝touch down、または同等の単発入力）。touch end では判定しない。スワイプ・慣性・コースト・カーリング型にしない |

やらないことも同じ重さで扱う。譜面・BGM・効果音・ランク表示、溜め（押し続けている時間で結果が変わる仕組み）、連打主軸、多ボタン、時間経過で恒常的に難しくなる上り坂は入れない。ホールド時間は成否に効かない。スワイプ・オービットを出荷候補に戻すこともしない。鋭スパイクは初出荷に入れない（9 章）。

## 5. 状態機械（phase）

盤の玩具は 1 つの状態機械で動く。同時に存在する接近は常に 1 本で、並行処理はない。v7 の phase は次の 7 つである。表と本文の「押し」は、開通コントロール上での touch down（pointerdown）を指す。

| phase | 意味 | 入るとき | 出るとき |
|---|---|---|---|
| `idle` | STANDBY。次の接近を待つ | 起動、判定後の linger 終了 | `gapUntil` 到達で `beginApproach` |
| `approach` | 針が動いている。押しを判定する | `armApproach` | 押しで判定、または針が端に着いて見送り |
| `interlock` | まれな連動灯列の挿入。ボタン無効 | `beginApproach` で 4% 抽選 | 灯列終了で `approach`。運休化・セッション終了で中断 |
| `barrier` | まれな遮断拍フラッシュ | `beginApproach` で 3% 抽選 | 120ms 後に `approach` |
| `easedown` | tier が上がった直後の「締まる」短い拍（名前は v6 の名残） | 前回クリアで tier が上がった | 180ms 後に `approach` |
| `resolved` | 判定直後の余韻（linger） | 良／可／不可／見送り | linger 後に `idle`、または満線で `calm` |
| `calm` | セッション終了。盤は静かになる | 40 秒経過、または 14 クリア | 再開操作でのみ `idle`（自動再開しない） |

遷移の順序は次のとおりで、毎接近の頭で `beginApproach` が帯と速度を抽選し直す。

```
起動 ─(bootGapMs 260)→ idle ─(gap)→ beginApproach
  beginApproach:
    tier 上昇の保留あり → easedown(180ms) → approach
    乱数 < 0.04         → interlock(≈175ms) → approach
    乱数 < 0.07         → barrier(120ms) → approach
    それ以外             → approach
  approach ─押し/端到達→ resolved ─linger→ idle（次の gap は nextAfter*）
                                    └ 満線保留 → calm
  どの phase でも sessionMs 経過 → calm
```

phase ごとの入力の扱いは、判定と同じくらい手触りに効く。扱いを分けるのは押した瞬間（touch down）で、下の表のとおりにする。開通コントロール以外から始まったタッチの down は判定しない。

| phase | 押されたとき |
|---|---|
| `approach` | 押した時刻で判定（6 章） |
| `idle`／`barrier`／`resolved`（pressLock 後） | 空押し jam（不可扱い。コンボも切れる） |
| `resolved`（pressLock 50ms 以内） | 無視 |
| `interlock` | 軽い却下 Taptic と「連動中 — まだ早い」。コンボは切らない |
| `easedown` | 無視（文言も出さない） |
| `calm` | 無視（ボタン無効） |

システムジェスチャなどでタッチがキャンセルされた（touch cancel）場合は判定も jam もしない。

## 6. 判定

判定は太鼓の達人の良／可／不可に倣う。広い可帯で通すのが安全側、中央の細い良帯を狙うのが報酬側で、スプラトゥーン1 の待機ミニゲームと同じ risk／return になる。

判定には開通コントロール上の touch down の時刻（pointerdown のタイムスタンプ）を使う。touch end（指を離す）では判定しない。ホールド時間は成否に効かない。進捗は `u = (押した時刻 − 接近開始時刻) / 今回の接近時間` で求め、0〜1 に丸める。描画フレームごとの針位置で判定してはいけない。良帯は片側 10〜15ms しかなく、60fps の 1 フレーム（約 16.7ms）より狭いからだ。

v7 プロト（`index-v7.html`）も本体も touch down で判定し、帯幅の数値もその状態で感触確定した。数値を変える場合は 1 章の手順（v7 と比較し、理由を追記してから変える）に従う。仕様初稿は touch end を想定していたが、実機で爽快感が薄れたため Issue #61 で touch down に戻した（2026-10-06）。

帯は毎接近の頭で次の手順で決まる。早側は遅側より狭く、早押しは高くつく。

1. 今回の値を抽選する: `接近時間 = round(approachMs × approachMul × 揺れ)`、`可半幅 = goodHalfW × goodMul × 揺れ`、`中心 = goodCenter + 揺れ`（0.44〜0.58 に収める）、`良半幅 = max(minPerfHalfMs / 接近時間, perfectHalfW0 × perfMul × 揺れ)`
2. 帯を置く: `可L = max(0.08, 中心 − 可半幅 × earlyGoodMul)`、`可R = min(0.92, 中心 + 可半幅)`、`良L = max(可L + 0.003, 中心 − 良半幅 × earlyPerfMul)`、`良R = min(可R − 0.003, 中心 + 良半幅)`
3. 判定する: `良L ≤ u ≤ 良R` なら良、`可L ≤ u ≤ 可R` なら可、それ以外は不可（`u < 中心` なら「早」、それ以外は「遅」）

揺れ（単調さ対策）は v7 の配列をそのまま使う。

| 揺れ | 値（等確率で 1 つ選ぶ） |
|---|---|
| `approachMsJitter` | 0.95, 1.0, 1.0, 1.04 |
| `goodHalfWJitter` | 0.92, 0.97, 1.0, 1.04 |
| `perfectHalfWJitter` | 0.92, 1.0, 1.0, 1.06 |
| `goodCenterJitter` | −0.03, −0.015, 0, +0.015, +0.03 |

結果は 5 種類あり、どれもループを止めない。

| 結果 | 条件 | コンボ | 盤の反応 |
|---|---|---|---|
| 良（Perfect） | 良帯で押した | heat +1.0 | 黄縁フラッシュ、全ランプのシマー、濃い通過。Taptic 最重 |
| 可（Good） | 可帯・良帯外で押した | heat +0.5 | 緑縁、部分シマー、通過 |
| 不可（Miss） | 接近中に帯外で押した | 切れる | 盤の揺れ、赤ストロボ、針が赤で止まる、×印、早／遅の表示。列車は通らない |
| 見送り（Timeout） | 押さないまま針が端（u=1）に到達 | 切れる | 軽い不可（赤のみ、揺れなし） |
| 空押し jam | 接近がないときに押した | 切れる | ボタンが横に噛む。260ms 入力を受け付けない。「早すぎ（てこが噛んだ）」 |

判定ラベル（良／可／不可／早／遅／見送り）は短い固定の文字で出してよい。数値ではないからだ。ただし tier に応じて添え書きを変えない（v7 の「良 — 芯を捉えた」のような段ごとの称賛文は持ち込まない）。点数・連続数・残りクリア数も出さない。

| 1 | 1086ms | 543ms | −46 / +65ms | −11.0 / +13.0ms |
| 2 | 1003ms | 502ms | −38 / +53ms | −10.2 / +12.0ms（下限） |
| 3 | 944ms | 472ms | −32 / +45ms | −10.2 / +12.0ms（下限） |

判定から次の接近開始までの死時間は、linger と nextAfter の和で決まる。良 170ms、可 135ms、不可 290ms、見送り 230ms で、v6 からそれぞれ約 6 割減らした値である。nextAfter の値は STANDBY の長さそのものになる。v7 のコードでは起動・再開・判定後のどの経路も待ち時間を明示して渡すため、`gapStepsMs` の抽選に到達する経路がない。感触はこの状態で確定したので、本体でも nextAfter と bootGapMs だけで STANDBY を決め、`gapStepsMs` は値だけ残しておく。例外として、運休中は STANDBY を最低 520ms に伸ばす。

## 8. コンボ熱＝難易度と落ち

難易度はコンボ熱（heat）だけで決まる。時間経過やクリア数で段が上がる仕組みは v6 で廃止した。熱いほど帯が細く接近が速くなり、切れると tier 0 へ戻る。何分遊んでも、tier 0 の窓はいつも同じ広さである。

heat は良で +1.0、可で +0.5 加算し、`heatTiers` で tier を決める。tier が上がったクリアの次の接近だけ、`easedown` phase で 180ms の「締まる」拍を挟む。この拍では、旧帯の残像から帯が縮む演出、段ピップの点灯とランプ色の切り替え、tier 上昇の Taptic を出し、可半幅を直前の 0.92 倍以下に抑える。v7 にある段名のバナーと「〈段名〉 · 締まる」の表示は持ち込まない。押しは受け付けない。

コンボが切れる条件は 4 つで、どれも heat を 0、tier を 0 に戻す。

- 不可（接近中の帯外の押し）
- 見送り（押さずに通過）
- 空押し jam
- `comboIdleMs`（2400ms）のあいだクリアがない。ただし `interlock`／`easedown` 中は時計を止める（期限を「現在＋500ms」以上に保つ）。`barrier` と `easedown` は期限にそれぞれの保持時間を足す

切れたときに tier が 1 以上なら「落ち」を見せる。帯が tier 0 の広さへ広がる演出、縁の熱グローが冷める演出、ランプが右から左へ柔らかいシアンで落ちる演出、柔らかい下降 Taptic を出す。伝えたいのは「あー残念、イージーに戻った」程度の惜しさで、叱責ではない。赤い警告、ブザーの追加、点数の減算表示、「また失敗」のような文言は入れない。tier 0 で切れたときは落ちの演出を出さない。v7 の「落ち」バナーと「熱が冷めた — 帯が戻る」の文は、出すかどうかを 14 章に残す（ランプ演出だけで足りるなら出さない）。

コンボの汁（FX と Taptic の濃さ）も同じ heat に追従する（7 章 `HEAT_DIFF` 表の「画面での見え方」）。難易度と汁が同じ軸に乗るので、プレイヤーには「熱いほど気持ちよく、危うい」ことが数字も段名もなしで伝わる。

## 9. 鋭スパイク（初出荷対象外）

鋭スパイクは初出荷に入れない（2026-10-05 決定）。本体には実装しない。7 章の `spike*`／`sharp*` の値は将来の比較用に残すだけで、コードから参照しない。白金の細い帯、▼印、鋭のラベルと予告、鋭良の Taptic もすべて対象外である。

記録として v7 の挙動を残す。良が 2 連続すると次の 2 接近だけ良帯を `perfectHalfW0 × perfMul × 0.70` に細くし（下限 `minPerfHalfMs`）、4 接近目以降は 6% の確率で単発の鋭が出る。v7 の数値では tier 2・3 の良帯がすでに 12ms の下限に張り付いているため、鋭は tier 0・1 でしか帯幅を変えていなかった。鋭を外したので、この点を直す必要はない。

## 10. 運行帯（世界観）と玩具の境界

盤の上端には運行帯（運行中｜運休｜停車）を常時表示する。玩具はこの帯の下で動き、本物の状態は端で読ませる。注意を全部奪わず、催促もしない（Calm Technology の考え方）。

運行帯は初出荷から本物の運休・停車の状態に配線する。見た目だけのダミーや、プロトの「運行帯タップで状態が循環する」仕組みは本体に入れない。運行帯が示すのは、出荷初日からアプリ本体の実際の運行状態である。

| 層 | 見え方 | 意味 |
|---|---|---|
| 玩具（接近クリアランス） | シアン系のランプ・針・開通ボタン | 切符に触れない回送玩具 |
| 運行中 | シアン点灯の「運行中」セル | サービスが回っている気配 |
| 運休 | 盤全体を減光・彩度ダウン（プロトは明度 0.42／彩度 0.35）。運行帯だけは減光しない | 本物の運休。赤警告にはしない |
| 停車 | 琥珀ランプと縁の薄い琥珀ウォッシュ | 待っている切符の気配。失敗の赤とも玩具のシアンとも区別する |

玩具は本物の状態を上書きしてはいけない。tier 3 の演出で光らせてよいのは「運行中」ランプだけで、運休・停車のランプは玩具の演出で点滅させない。運休中も玩具は遊べるが、STANDBY を最低 520ms に伸ばし、連動灯列は中断する。ヒント文も「運休中の回送接近…」「停車気配あり · 接近中…」に変える。2 章のパターン B で盤を気配表示にしているときも、運行帯は同じ情報を読めるように残す。

玩具と本物の境界は次の 3 点で守る。

- 回送玩具の操作から `startService()` を呼ばない
- 切符の題名を出さない
- 到着としてクレジットしない（到着数・実績・履歴に数えない）

## 11. フィードバック（Taptic／視覚）

フィードバックの主役は Taptic である。初出荷では音を出さず、SOUND の設定 UI も作らない。Taptic と視覚だけで手触りが成立する前提で作る。称賛は FX と Taptic の強さで表し、数値や文言で表さない。

HTML プロトの振動は `navigator.vibrate` による代用品にすぎない。iOS Safari ではほぼ動かず、代わりに盤右上の HAP ランプが同じタイミングで光る。したがって下の表は、強さの順序と拍の形を伝える目安として読む。出荷品ではネイティブの Taptic Engine 実装が必須で、ms 列をそのまま移しても出荷品質にはならない。

v7 パターンからネイティブ Taptic への対応づけは、Todo列車のデザイン側が持つ。実装担当は下の強さの順序を守ればよく、`UIImpactFeedbackGenerator` を使うか `CHHapticPattern` を組むかといった具体的な選定は、順序が保たれる限り後から決めてよい。

| 事象 | v7 パターン（ms、振動・休み交互） | 意図 |
|---|---|---|
| 接近キュー | 単発 10。u ≥ 0.28 から可帯手前まで、間隔 `70 + 残り距離 × 280` ms で詰まる | カウントイン |
| 良（tier 0→3） | [48,16,78] → [54,14,88] → [58,12,34,12,92] → [62,10,40,10,104] | 重いメカクリック。tier で重くなる |
| 可（tier 0→3） | [22,18,32] → [26,16,38] → [30,14,44] → [32,12,20,12,50] | 通った感を残した短い噛みつき |
| 不可 | [42,24,42,24,70] | 可より重い多連の却下。刺さりを残す |
| 見送り | [26,30,26] | 軽い不可 |
| 空押し jam | [50,20,50] | てこが噛む |
| tier 上昇 | [10,36,14,36,22] | 締まる合図 |
| 落ち（コンボ切れ） | [18,40,28,50,40] | 柔らかい下降。罰ではない |
| 連動灯列 | 灯ごとに 8、完了で [10,20,24] | メカが噛む |
| 遮断拍 | [14,20,14] | 同上 |
| 満線で終了 | [24,60,24] | 控えめな締め |

（v7 の「鋭良」「鋭の接近開始」は 9 章のとおり対象外。）

強さの順序は守る。良が可より重く、不可は可より重く、落ちは不可より柔らかい。プロトでは後から呼んだ振動が前の振動を打ち消すため、tier 上昇の合図は直後の良／可の振動で上書きされている。本体では順に鳴らす方を優先し、良／可の判定の手応えが後続の振動で消えないようにする。細部の調整はデザイン側が持つ。

視覚の要素は次のとおりで、どれも数値を出さない。

- 針と接近点（左→右）、可帯（緑）、良帯（中央の細い黄）、帯中心の白線、押した位置のマーク
- ランプ列（APPR／GOOD／PERF／CLR／REJ／ILK）、HAP ランプ
- 段ピップ（ランプ）の点灯数・色・強さと流れの速さ記号。段名の文字は出さない
- 列車シルエットの通過（約 0.28s）
- セッションの残りを示す細いバー（数字なし）

v7 にある tier ごとに変わるヒント文（「良 — 芯を捉えた」など）と、段名を含む文（「〈段名〉 — 帯が締まり、接近が速い」「〈段名〉 — 構えて」）は本体に持ち込まない。

## 12. セッション開始・終了

セッションは短く、静かに終わる。終わり方は責めず、続けるかどうかはプレイヤーが決める。フィジェットはご褒美であって沈み込み先ではないので、長く遊ばせる仕掛けは入れない。

開始は盤の表示（パターン B では利用者の操作で盤を展開したとき）、またはリセット・再開操作から数え、`bootGapMs`（260ms）後に最初の接近が来る。開始時に heat、クリア数、接近数を 0 に戻す。運行帯は現在の状態を保つ。

終了条件は 2 つある。

| 条件 | 表示 | 演出 |
|---|---|---|
| `sessionMs`（40 秒）経過 | 「閑散」／「回送おわり · また近づくとき」 | 盤が静かになる |
| クリア数が `sessionFullClears`（14）に到達 | 「満線」／「回送は満ちた · また近づくとき」 | 控えめなランプ連鎖と [24,60,24]。ファンファーレにはしない |

満線は判定の linger 後に入り、最後が良なら 120ms 余分に待つ。v7 の数値で全部良を取ると、概算 10 秒前後で満線になる（v4 のヘッドレス検証値「約 20 秒」は接近が長かった頃の数字）。

終了後の扱いは次のとおりに決める。

- 盤は静かな盤のまま残す。開通ボタンを無効にし、heat を落とし、針を隠す
- 自動で次のセッションを始めない。再開はプレイヤーの明示的な再開操作だけで行う
- 再開や「もう一回」を促す表示、点滅、通知、バッジを出さない
- クリア数、良の数、最長コンボ、「今日の記録」の類を出さない

## 13. 受け入れ条件（要約）

詳細な判定項目は `実装_受け入れ条件_v7.md` にまとめた。要点は次の 9 つである。

- 7 章の定数と `HEAT_DIFF` が一致し、実効窓が 7 章の表と揃う（debug 表示で検算できる）
- 判定が touch down（指を載せた瞬間）で行われ、touch end やフレームの針位置に依存しない
- 不可・見送り・jam でもループが止まらず、死画面・責め文言・数値が出ない
- Taptic と視覚だけで良／可／不可の違いが分かる。音と SOUND 設定 UI がない
- 難易度がランプの色と強さだけで示され、段名の文字が画面に出ない
- 玩具の操作が `startService()`、題名表示、到着クレジットのどれにも触れず、運休・停車が同じ盤で読める
- 運行帯が初出荷から本物の運休・停車を示す
- 約 40 秒または 14 クリアで静かに終わり、自動再開も再開の催促もしない
- 鋭スパイクが入っていない
