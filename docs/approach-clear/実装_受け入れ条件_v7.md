# 接近クリアランス 受け入れ条件（v7 凍結）

日付: 2026-10-05（Asia/Tokyo）／同日 プロダクトオーナー決定を反映
本文: `実装仕様_接近クリアランス_v7.md`
正本: `index-v7.html` の `const P` と `HEAT_DIFF`（数値のみ。判定トリガー・表示・音・鋭は仕様 14 章が優先）

この一覧は出荷判定に使う。各項目は「はい／いいえ」で判定できる形にした。仕様 14.2 の未決事項に依存する項目は含めていない。難易度の段は tier 0〜3 と書く。

## 席・見た目・入力

- 盤は Hub の「盤」に置かれ、運行帯（運行中｜運休｜停車）と同じ面にある
- 盤の見せ方は常設盤（A）か気配表示→展開（B）のどちらかで、玩具だけの独立画面・全画面がない
- 見た目はメカ／機械クールなパネルで、実在の車両・駅名・ダイヤを描かない
- 入力は開通ボタンでの単発の離し（または同等の単発入力）だけで遊べる
- スワイプ・フリック・慣性・コースト・溜め（載せている時間で結果が変わる）・連打を要求しない
- 回送オービット（スワイプ）の操作が盤に残っていない
- ホームウィジェット（窓）に接近クリアランスが載っていない

## 判定

- 判定に touch end（指を離した時刻）のタイムスタンプを使う
- touch start（押し始め）では判定しない。指を載せただけではどの phase でも何も起きない
- 描画フレームの針位置を判定に使わない
- 指を載せたまま `idle` から `approach` に入っても jam にならない
- touch cancel は判定せず、jam にもならない
- 揺れ 1.0 の tier 0 で、可帯が帯中心から −56／+78ms、良帯が −13.0／+15.3ms になる
- tier 2・3 で、良帯の遅側半幅が 12ms を下回らない
- 早側が遅側より狭い（可 ×0.72、良 ×0.85）
- 接近中の帯外の離しは不可、離さずに端到達は見送り、接近なしの離しは早離し jam になる
- 早離し jam のあと 260ms は入力を受け付けない
- 判定直後 50ms の離しは無視される
- `interlock` 中の離しは軽い却下だけで、コンボを切らない
- `barrier` 中の離しは早離し jam になる

## 時間（死時間）

- 判定から次の接近開始まで: 良 170ms、可 135ms、不可 290ms、見送り 230ms（運休中は STANDBY 最低 520ms）
- 起動・再開から最初の接近まで 260ms
- tier 上昇直後の「締まる」拍が 180ms で、その間の離しは無視される
- 連動灯列は 3 灯 × 45ms（全体約 245ms）で、出現率は約 4%
- 遮断拍は 120ms で、出現率は約 3%
- 2400ms クリアがないとコンボが切れる（interlock・締まる拍の間は数えない）

## コンボ熱

- heat は良 +1.0、可 +0.5。しきい 1.5／3／5 で tier 0→1→2→3
- tier ごとの倍率が `HEAT_DIFF` と一致する
- 不可・見送り・jam・2400ms 無クリアで heat が 0 になり、tier 0 の帯幅へ戻る
- tier 1 以上で切れたとき「落ち」演出（帯が広がる・グローが冷める・柔らかい下降 Taptic）が出る
- 落ちの演出に赤警告・ブザー追加・減点表示・責め文言がない
- 時間経過やクリア数で窓が狭くならない（tier 0 の窓は 40 秒目でも 1 秒目と同じ）

## 鋭スパイク（初出荷対象外）

- 鋭スパイク（良 2 連後の ×0.70）と単発の鋭（6%）が実装されていない
- 白金の細い帯、▼印、鋭のラベル・予告、鋭良の Taptic が出ない

## 数値・段名を出さない

- 通常画面に点数・連続数・回数・残りクリア数・残り秒数の数字が出ない
- 難易度はランプ（段ピップ・連鎖）の色と強さだけで示され、段名の文字（一字の漢字ラベル、v7 の `HEAT_DIFF[].name`）が画面のどこにも出ない
- tier 上昇時に段名のバナーや「〈段名〉 · 締まる」の表示が出ない
- tier ごとに変わる称賛ヒント文（v7 の「良 — 芯を捉えた」など）が出ない。判定ラベルは固定の短い文字だけ
- 終了画面にクリア数・良の数・最長コンボ・記録が出ない
- 数値の表示は debug ビルド限定で、リリースビルドからは到達できない

## フィードバック

- ネイティブの Taptic Engine で鳴る（HTML の vibrate を出荷品と見なさない）
- 強さの順序: 良 ＞ 可、不可 ＞ 可、落ち ＜ 不可
- 良・可の Taptic が tier に応じて重くなる
- 接近キューの弱いパルスが、窓に近づくほど間隔を詰める
- tier 上昇の合図が重なっても、良／可の判定の手応えが消えない
- 音が一切鳴らない
- SOUND（音）の設定 UI がどこにもない
- 端末ミュートの有無にかかわらず、良／可／不可の違いが Taptic と視覚だけで分かる
- 称賛が FX と Taptic の強さで表され、数値や文言で表されない

## 失敗の扱い

- 不可・見送り・jam のどれでもループが続き、次の接近が来る
- 死画面・ゲームオーバー・リトライ要求がない
- 空白日の催促、ストリーク、出席扱い、通知がない

## 玩具と本物の境界

- 玩具の操作で `startService()` が呼ばれない
- 玩具の画面に切符の題名が出ない
- 玩具のクリアが到着・実績・履歴に数えられない
- 運行帯が初出荷から本物の運休・停車の状態を示す（ダミー値・固定値でない）
- 運休中は盤全体が減光し、運行帯は読めるまま残る
- 停車は琥珀で示され、失敗の赤とも玩具のシアンとも区別できる
- 玩具の演出で運休・停車のランプが点滅しない（光ってよいのは「運行中」だけ）
- プロトの「運行帯タップでダミー循環」が本体に入っていない
- 気配表示（パターン B）のときも運行帯の運休・停車が読める

## 注意を奪わない（製品上の役割）

- タスク完了画面にフィジェットのオーバーレイや遊びへの誘いが出ない
- 盤へ戻るよう促す表示・通知・バッジがない
- パターン B では、利用者が盤に触れるまで気配表示のままで、針・接近・Taptic が動かない
- パターン B の展開が、時間経過・タスク完了・通知をきっかけに自動で起きない

## セッション

- 40 秒経過で「閑散」になり、盤が静かになる
- 14 クリアで「満線」になり、控えめな締めの演出が出る
- 終了後は開通ボタンが無効になる
- 終了後に自動で次のセッションが始まらない。再開は明示的な再開操作だけで起きる
- 終了後に再開や「もう一回」を促す表示・点滅・通知が出ない
