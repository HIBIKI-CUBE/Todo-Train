# 13 — 同期構成（なぜこの形か）

ワイヤのバイト・経路・黄金 JSON の正本は [`sync/contract/`](../sync/contract/README.md)。Mac の体験は [14](14-mac-companion-ux.md)。製品の守ること・やらないことの正本は [02](02-requirements.md)。

## なぜこの形か

iPhone の SwiftData + `SessionManager` が本尊。リレーは正本にしないし、復号できない。

運ぶのは **いまの乗務** の暗号スナップショットと、コマンド `pause` / `resume` / `still` / `issueAndBoard`。`issueAndBoard` は Mac の「いまやる」一拍（題名と所要を送り、母艦が発行して発車する）。在庫のみ発行・切符全件レプリカ・CRDT は載せない。`arrive` / `extend` を足さない。成功の中身は ack ではなく後続 snap。

iOS は前面、または `ScenePhase.active` で送受信する。ロック中に「いまやる」が届くことは、この slice の約束にしない。

土管は Cloudflare Workers + pairing 1 = Durable Object 1。アカウントなし。起こし（APNs）を求めない。Personal Team のまま動く。

機密: 正規ユーザー以外は中身を見られない（Apple / 自前サーバ / 押収を含む）。だから CloudKit 私有同期はこの土管に使わない。鍵が Apple 側にある。暗号文だけ載せるなら自前同期と同じ仕事になる。

LAN / Bonjour は社内 Wi-Fi のクライアント分離で届かないことが多い。主経路にしない。

購読者は同じ契約ならよい。メニューバーであることは前提にしない。

ビルドの識別（コミット・dirty・スキーマ版・作られた時刻）は暗号文の中だけを往復する。リレーは SHA を見ない。iPhone は snap と ack に自分のビルドを載せ、Mac は cmd に自分のビルドを載せる。相手が古い平文でも項目は任意なので復号は壊れない。SHA が両方とも記録されていて違うときだけ、iPhone の設定が知らせる。同じなら黙る。まだ届いていなければ黙る。

相手と組み合わせてよいかは、コミットやビルドの日時ではなく約束の版で見る。版がずれても、知っている部分の走行と停車の表示は続ける。操作を送らないのは、相手が古すぎてその操作を誤読するときだけである。同期そのものを止めるのは、鍵が合わないときだけである。

## ペアリングの脅威

画面は常時録画されている前提。スクショも後ろ撮りも、映像を別マシンで読むことも中の脅威。画面に出るものは全部漏れる。確定に使うのは **画面に出ない秘密** と **その場の本人確認** だけ。

照合数字は人の防御にしない（見ない）。「どの Mac か」は、画面を机の Mac に向ける同時光学交換（セルフィー）。「本人か」は光学のあと、端末を自分に戻してからの Face ID / Touch ID。セルフィー中は顔が画面側に無いので、同じ姿勢で Face ID しない。

両方のカメラが揃うまでリレーに相手を固定しない。片側の QR 読取や「許可しますか」だけでは、録画の先着がペアになる。双方の本人確認が終わるまで Keychain に書かない。

`masterKey` / `writeToken` / confirm HMAC は QR にも貼り付けにも出さない。点滅 QR で秘密を分割しない（全フレームが残る）。リカバリを出すなら書き写しのみ。QR にしない。

カメラ無し Mac の貼り付けフォールバックはやらない。ウェブカメラ必須。

サーバ侵害の残りは削除 DoS。許容する。

## この面のやらないこと

アカウント、APNs、LAN 主経路、サーバ側正本、画面に載る長期鍵、片側タップ確定、照合数字の目視、裏カメラへの持ち替え。CloudKit と JSON エクスポート同期は [02](02-requirements.md)。Watch の写しはリレーに載せない。iPhone から WatchConnectivity で渡す（[23](23-watch.md)）。
